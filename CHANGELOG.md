# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- Add a note to the run payload that says why a run is inconclusive when its interval is wider than the expected effect. [feat:experiments]
- Fail a confirmation run, before it writes any file, when the games scored differ from the cohort count or the run has no interval. [feat:experiments]
- Add `hockey-model refresh --retry-skipped`, which reads again the score days, boxscores, and MoneyPuck files that earlier reads skipped as known gaps. [feat:store]
- Stop the MoneyPuck reads of a refresh when the time budget is spent, after the first file of the run, and say so in the notes. [feat:store]
- Name a boxscore game that a write leaves listed as missing, and read one game at most once in a refresh. [feat:store]
- Scale the promotion bar of a confirmation record with its look number: look `k` promotes only when the upper end of the interval from the `BASE_TAIL / k` tail lies below zero, and a confirmation record must set `look_number` to one more than the earlier confirmation records. [feat:experiments]
- Add a note to the run payload when the confirmation season floor moves the first scored season. [feat:experiments]
- Add a TLA+ model of the daily prepare backfill, checked by TLC in a `tla` CI job and by `scripts/tlc.sh`. [feat:store]
- Add `hockey-model refresh --reread-moneypuck`, which reads the MoneyPuck files even when they are fresh. [feat:store]
- Add the typed player, roster, projection, matchup, playoff, and JSON CLI APIs. [feat:types]
- Add the Game input and game_win_probability() for one NHL game's home and away win chance, with a GameModel protocol that a model implements. Game rejects a team code that is not an NHL code. [feat:api]
- Add an SQLite store at the HOCKEY_MODEL_DB path, which refuses a store made by another schema version. [feat:store]
- Add a polite HTTP client that spaces requests per host and retries rate limits, server errors, and network failures. A response body that takes more than 120 s fails with a named error. [feat:sources]
- Add NHL team code maps for ESPN's four renamed codes and the Arizona to Utah franchise history. [feat:sources]
- Add NHL API score-day and boxscore reads, and store them as dated reads that keep earlier reads. [feat:sources]
- Add MoneyPuck team and goalie game-by-game reads (expected goals), stored as dated reads that keep earlier values. Data from MoneyPuck.com. [feat:sources]
- Add ESPN probable starting goalie and injury reads, and Daily Faceoff starting goalie reads, stored as dated reads. [feat:sources]
- Add `hockey-model refresh`, which reads every source into the store, keeps each source failure apart, and exits 1 when a source failed. [feat:store]
- Add as-of reads of the store and starting goalie resolution: the goalie on the game, the boxscore starter after puck drop, the first confirmed read, the newest likely read, then the goalie with the most recent starts. [feat:store]
- Add the NHL Elo (K 8, home advantage 28, log-margin scaling, same as sportsbettr without the market shrink) and the game features: expected-goals form, goalie goals saved above expected, and rest. [feat:model]
- Add the logistic game model: `hockey-model fit` fits and saves the weights, and `hockey-model game GAME_ID` prints the win chances, expected goals with a Poisson interval, and the missing inputs. [feat:model]
- Add backtest scores: log loss, Brier score, a ten-bin calibration table, and a block bootstrap interval for a mean. [feat:backtest]
- Add `hockey-model backtest`, a walk-forward backtest that refits before each scored season, tests all features together against the results-only Elo, and writes per-game predictions with `--games-out`. [feat:backtest]
- Add mutation testing with mutmut: `uv run mutmut run` mutates the parsers and the rate math, and an advisory CI job reports the survivors without failing the build. [chore:test]
- Add a `smoke` CI job and `scripts/smoke_wheel.py`, which build the wheel, install it alone in a clean venv, and predict one game from a seeded store. [chore:ci]
- Add zizmor to the prek hooks and to a `zizmor` CI job, both at v1.32.0, to scan the workflows. [chore:ci]
- Python project skeleton: uv, ruff, ty, pytest with coverage and a per-module floor, editorconfig, prek hooks, and CI validation, test, and editorconfig jobs.
- Certify each logistic fit by the gradient of the penalized loss and save its diagnostics (iterations, objective, gradient, conditioning, penalty, scaling, stop reason) with the fit. A clipped step no longer counts as convergence. [feat:model]
- Add the November 2026 backtest report. The joint test passed with expected-goals form and rest, and the guess run vetoed goalie goals saved above expected. [docs:backtest]
- Add `hockey-model backtest --candidates attempt`, which replaces the expected-goals form with a shot-attempt form for the leak test. [feat:backtest]
- Add the experiment registry: records in `experiments/`, `hockey-model experiments check`, and `hockey-model experiments run`. A confirmation record scores only games after its data cutoff in the 2026-27 regular season and later, runs once, and refuses a cohort smaller than its minimum. An exploration record scores the seasons through 2025-26 and may run again. The checker validates every schema keyword, compares immutable fields with the commit that registered the record, ties `status` to `result`, and fails a record whose committed result was removed or replaced. [feat:experiments]
- Add `hockey-model store upgrade`, which moves a version 1 store to the current schema. It keeps every row and fit ID, writes a backup first, and runs in one transaction. [feat:store]
- Add a pre-push mutation check. It runs mutmut on the functions that a push changes, and it fails on a survivor on a changed line, a timeout, or an incomplete result. [chore:test]
- Add a scheduled check that alerts when a game day with games has no `reports-DATE` release, or when every game row of its report was made after the start. A day with no games raises no alert. [feat:report]

### Changed

- Move the publish decision of the report gate into Python (`hockey-model report-decide`), so `scripts/report-gate.sh` only reads the schedule and the release. [chore:report]
- Read `data_cutoff` of a confirmation record as "data through this day", so games of the cutoff Eastern game day are no longer in the cohort. [fix:experiments]
- Predict a game that is over in the daily report, from the inputs known at its puck drop, so a late first report is full. A postponed game still gets no prediction. [feat:report]
- The attempt-form and expected-goals reads skip a MoneyPuck team game with a missing value, instead of failing on it. The 10-game window reaches one game further back in that case. [fix:store]
- The daily report run logs the seconds of each step and fails once it passes the limit in `REPORT_BUDGET_S`. The build job fails on a store cache miss. [chore:ci]

- Record the DraftKings comparison in the README, the backtest report, and the run report. The model is level with the line in 2024-25 and worse in 2025-26, and it fails the blend gate. [docs:backtest]
- Move the store to schema version 2, which adds MoneyPuck shot-attempt counts. A version 1 store is refused, so rebuild it on a new path with `hockey-model refresh --backfill-from 2014-10-01`. [feat:store]
- Require `--features` in `hockey-model fit`. The old default fitted every candidate, including `goalie_gsax`, which the backtest vetoed, and the daily report served that fit. `scripts/daily-prepare.sh` now runs the backtest first and fits on its `live_features`, so a failed joint test serves the Elo alone. [fix:cli]
- Name the feed games that fall outside a game day's window in the `report-due` output, instead of dropping them without a word. [refactor:report]
- Replace the daily report's release files and notes with each later build before the first puck drop. The release can therefore change until then, and its notes say so. [feat:report]

### Fixed

- Leave the same count of bootstrap means outside each end of the interval. The upper end moved one rank lower, so a promotion needs a slightly stricter result. [fix:backtest]
- Judge source staleness in one pass over the read log, so the daily predict step takes seconds and not minutes on a backfilled store. The build job no longer fails its report budget on this step. [fix:report]
- Stop a postponed row from hiding a late daily report in `check-daily-report.sh`. [fix:report]
- Publish the first daily report of a game day even when the run starts after the first puck drop, with a `late` gate reason and a warning. Before this, a late trigger published nothing. [fix:report]
- Fail a backfill that the time budget stops before it reads one older day or game. The last two days do not count, because a daily run completes the day that closed since the last run. Before, each run read the same recent days, stopped, and exited 75, so the backfill never finished and nothing said why. The refresh now exits 1 and names `--budget-seconds`. [fix:store]
- Read a failed NHL score day again on the next refresh, for 30 days. A day that failed and was followed by a good day was never read again, so its games were missing from the Elo and the fit. [fix:store]
- Refuse a boxscore that does not have exactly one starting goalie for each team. A boxscore without a goalie made the next refresh stop with a database error. [fix:sources]
- Read MoneyPuck numbers as plain ASCII decimals. A value such as 1_0 or a non-ASCII digit was accepted. [fix:sources]
- Refuse an ESPN return date that is not text, and a saved fit with an unknown feature or a weight that is not finite. [fix:sources]
- Match an injury name to the goalies of its own team only. [fix:model]
- Print the type and message of an unexpected failure in the store commands. [fix:cli]
- Note in the backtest report that the goalie guess run has no injury history. [fix:backtest]
- Publish the daily report at the first run that starts before the first puck drop. A run that starts after the puck drop publishes nothing and writes a warning. [fix:report]
- Fit the daily-prepare job timeout to the window before the next trigger hour. [fix:report]
- Publish no daily report for a game day with no games, so a failed schedule read cannot leave a wrong release. [fix:report]
- Give the daily report step its own time limit, so a hung read cannot hold the store for the full job limit. [fix:report]
- Allow an hour for the MoneyPuck team file, which is about 130 MB, instead of 15 minutes. [fix:sources]
- Check a fit before it is saved, accept every supported feature including `attempt_form`, reject a feature named twice, and predict with the features that the loaded fit names. A saved attempt-form fit failed with a `KeyError` at prediction. An Elo-only fit still credits MoneyPuck, since the goal rates use its data. [fix:store]
- Install the pre-push hook with a plain `prek install`, so the local coverage gate runs. [fix:ci]
- Name the editorconfig-checker config `.editorconfig-checker.json`, the name the tool loads, and download its archive into `RUNNER_TEMP`. [fix:ci]
- Check that a flag has a value in the report scripts, so `semgrep` parses them and a missing value gives a usage error. [fix:scripts]
- Report a `TypeError` from a model as an unexpected failure. Only a JSON encoder `TypeError` is a serialization failure. [fix:cli]
- Use one season boundary (`SEASON_START_MONTH`) and one season id formula for the fit, the cohorts, and the MoneyPuck refresh. [fix:model]
- Check every projection at each public entry point and refuse a value that is not finite, is out of range, or has an interval that does not hold the point. Goals against average may exceed one. [fix:api]
- Refuse a boxscore that does not name the stored game's teams in the stored home and away order, or that has no skater rows or no starting goalie for a team. A game with one side stored is queued again and repaired without a change to the old rows. [fix:sources]
- Read an unresolved game again after a wait, even when newer games are final. At most `MAX_UNRESOLVED_DAYS` days are read in one refresh, and the report names the games. [fix:store]
- Judge each source URL by its newest read and by age. A good read of one URL no longer clears a failed read of another, and an injury list older than `LIVE_FEED_MAX_AGE` is not used. [fix:store]
- Check a goalie supplied on a `Game` against the earlier of `as_of` and the start, and give it the same uncertainty note as a stored read. [fix:model]
- Leave a goalie out of the starter guess when the games show that the goalie had left the team. A goalie that a source names is not filtered. [fix:model]
- List a form feature that was set to `NEUTRAL_FORM` because a team had no MoneyPuck games in `degraded_inputs`, in the result, the command line output, and the daily report JSON. [fix:model]
- Show the scored games of each season and game type in the backtest report. Refuse `success` and leave `live_features` empty when a listed regular season is under `MIN_SEASON_COVERAGE` of its expected games, or when the scored games hold fewer than `MIN_INDEPENDENT_BLOCKS` blocks for the bootstrap. The bootstrap now raises for such a sample. [fix:backtest]
- Name the Eastern game day, not the UTC day, in the `daily` help, the daily report module docstring, and the `--date` help of `publish-daily-report.sh`. The code already selected the Eastern game day. [docs:cli]
- Read a finished score day again only until 7 hours after the Eastern game day closes, which is 12:00 UTC in winter and 11:00 UTC in summer. The old rule read a summer day one hour too long. [fix:store]
- Set a goalie differential to the neutral value when either starter has no rate, and mark the feature as imputed for that team. The other starter's rate no longer passes through as a measured difference. [fix:model]
- Refuse a fit, with exit 2 and no saved fit, when a selected feature is imputed in more than 10% of its training rows. A backtest vetoes such a candidate instead of stopping. The `imputation` list in the fit and backtest JSON gives the count and share for each selected feature. [fix:model]
