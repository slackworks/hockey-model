# Changelog

All notable changes to this project are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- Add the record status `withdrawn`. A withdrawn record spends no look, holds no result, never runs, and cannot return to another status. Only a registered record can be withdrawn, and a withdrawn record has no results file. `experiments check` reads the history to enforce this, and it reports a JSON file in the registry whose name is not a record id. Record 0001 is withdrawn before any result, and record 0002 replaces it as look 1 with the 97.5th percentile bar. `MAX_LOOKS` now follows the bootstrap resolution: it is the last look whose tail leaves `MIN_TAIL_RESAMPLES` resampled means outside each end. [feat:experiments]
- Add `schema_version` (1) to the published report JSON, with a JSON Schema for the report and for a new `index-DATE.json` release asset that lists every build of the day (`file`, `generated_at`, `code_sha`, `fit_sha256`, `inputs_sha256`, `schema_version`). `daily` checks the report against its schema before it writes, and `publish-daily-report.sh` runs the new `report-index` command, which checks the report and the index before any upload. Both schemas ship in the wheel, and the smoke test runs `daily` and `report-index` from the installed wheel. The `publish` job installs the project so the script can run the check. [feat:report]
- Add `open_store`, a read-only consumer API that pins one saved fit, reads one snapshot, and predicts a game or lists a day's games. `FitRef` selects the fit by id or by label, and `LIVE_LABEL` names the live fit. [feat:api]
- Add `GamePrediction.training`, which names the fit and says whether the game is `in_sample`, `out_of_sample`, or `unknown` for it. The CLI JSON, the daily report JSON, the report Markdown, and the consumer result carry it. [feat:model]
- Add a refresh note that counts the MoneyPuck rows that match no stored game, and the rows whose game is not final yet, and add a `stale_source` note to a prediction whose team's newest MoneyPuck game is older than its newest final game. [feat:store]
- Add a note to the run payload that says why a run is inconclusive when its interval is wider than the expected effect. [feat:experiments]
- Fail a confirmation run, before it writes any file, when the games scored differ from the cohort count or the run has no interval. [feat:experiments]
- Add `hockey-model refresh --retry-skipped`, which reads again the score days, boxscores, MoneyPuck files, and live feeds that earlier reads skipped as known gaps. [feat:store]
- Stop the MoneyPuck reads of a refresh when the time budget is spent, after the first file of the run, and say so in the notes. [feat:store]
- Name a boxscore game that a write leaves listed as missing, and read one game at most once in a refresh. [feat:store]
- Scale the promotion bar of a confirmation record with its look number: look `k` promotes only when the upper end of the interval from the `BASE_TAIL / (k * (k + 1))` tail lies below zero, so the tails of all looks sum to less than `BASE_TAIL`, and a confirmation record must set `look_number` to one more than the earlier confirmation records. [feat:experiments]
- Add a note to the run payload when the confirmation season floor moves the first scored season. [feat:experiments]
- Add a TLA+ model of the daily prepare backfill, checked by TLC in a `tla` CI job and by `scripts/tlc.sh`. [feat:store]
- Add `hockey-model refresh --reread-moneypuck`, which reads the MoneyPuck files even when they are fresh. [feat:store]
- Add the typed player, roster, projection, matchup, playoff, and JSON CLI APIs. [feat:types]
- Add the Game input and game_win_probability() for one NHL game's home and away win chance, with a GameModel protocol that a model implements. Game rejects a team code that is not an NHL code. [feat:api]
- Add an SQLite store at the HOCKEY_MODEL_DB path, which refuses a store made by another schema version. [feat:store]
- Add a polite HTTP client that spaces requests per host and retries rate limits, server errors, and network failures. A response body that takes more than 120 s fails with a named error. [feat:sources]
- Add NHL team code maps for ESPN's four renamed codes and the Arizona to Utah franchise history. [feat:sources]
- Add NHL API score-day and boxscore reads, and store them as dated reads that keep earlier reads. [feat:sources]
- Add MoneyPuck team and goalie game-by-game reads (expected goals), stored as dated reads that keep earlier values. Data from MoneyPuck.com. [feat:sources]
- Add ESPN probable starting goalie and injury reads, and Daily Faceoff starting goalie reads, stored as dated reads. [feat:sources]
- Add `hockey-model refresh`, which reads every source into the store, keeps each source failure apart, and exits 1 when a source failed. [feat:store]
- Add as-of reads of the store and starting goalie resolution: the goalie on the game, the boxscore starter after puck drop, the first confirmed read, the newest likely read, then the goalie with the most recent starts. [feat:store]
- Add the NHL Elo (K 8, home advantage 28, log-margin scaling, same as sportsbettr without the market shrink) and the game features: expected-goals form, goalie goals saved above expected, and rest. [feat:model]
- Add the logistic game model: `hockey-model fit` fits and saves the weights, and `hockey-model game GAME_ID` prints the win chances, expected goals with a Poisson interval, and the missing inputs. [feat:model]
- Add backtest scores: log loss, Brier score, a ten-bin calibration table, and a block bootstrap interval for a mean. [feat:backtest]
- Add `hockey-model backtest`, a walk-forward backtest that refits before each scored season, tests all features together against the results-only Elo, and writes per-game predictions with `--games-out`. [feat:backtest]
- Add mutation testing with mutmut: `uv run mutmut run` mutates the parsers and the rate math, and an advisory CI job reports the survivors without failing the build. [chore:test]
- Add a `smoke` CI job and `scripts/smoke_wheel.py`, which build the wheel, install it alone in a clean venv, and predict one game from a seeded store. [chore:ci]
- Add zizmor to the prek hooks and to a `zizmor` CI job, both at v1.32.0, to scan the workflows. [chore:ci]
- Python project skeleton: uv, ruff, ty, pytest with coverage and a per-module floor, editorconfig, prek hooks, and CI validation, test, and editorconfig jobs.
- Certify each logistic fit by the gradient of the penalized loss and save its diagnostics (iterations, objective, gradient, conditioning, penalty, scaling, stop reason) with the fit. A clipped step no longer counts as convergence. [feat:model]
- Add the November 2026 backtest report. The joint test passed with expected-goals form and rest, and the guess run vetoed goalie goals saved above expected. [docs:backtest]
- Add `hockey-model backtest --candidates attempt`, which replaces the expected-goals form with a shot-attempt form for the leak test. [feat:backtest]
- Add the experiment registry: records in `experiments/`, `hockey-model experiments check`, and `hockey-model experiments run`. A confirmation record scores only games after its data cutoff in the 2026-27 regular season and later, runs once, and refuses a cohort smaller than its minimum. An exploration record scores the seasons through 2025-26 and may run again. The checker validates every schema keyword, compares immutable fields with the commit that registered the record, ties `status` to `result`, and fails a record whose committed result was removed or replaced. [feat:experiments]
- Add `hockey-model store upgrade`, which moves a version 1 store to the current schema. It keeps every row and fit ID, writes a backup first, and runs in one transaction. `--if-missing skip` exits 0 when the store file does not exist, for a first run that writes one later. [feat:store]
- Add a pre-push mutation check. It runs mutmut on the functions that a push changes, and it fails on a survivor or a timeout on a changed line, on any other incomplete result, and on a mutant whose line it cannot find. A timeout off the changed lines is listed and does not fail the push. [chore:test]
- Add a scheduled check that alerts when a game day with games has no `reports-DATE` release, or when every game row of its report was made after the start. A day with no games raises no alert. [feat:report]
- Skip the backtest and the fit in `daily-prepare.sh` for a day that has its `prepared-DATE` marker and a valid `backtest-DATE.json`. The refresh still runs. `--force`, and the `force` input of a manual `daily-prepare` run, rebuild the day. [feat:report]
- Add `inputs_sha256` to the daily report JSON, and add `hockey-model report-compare` with `daily-report.sh --skip-unchanged`. A report build that has the inputs of the newest published report does not publish. [feat:report]
- Add `hockey-model backtest --workers N`, and the same option of `hockey-model experiments run`. They build the feature rows one season at a time in worker processes, each season from the Elo ratings before its first game, and log the wall time of each unit. The report and the per-game CSV do not change with N. `daily-prepare.sh` passes `BACKTEST_WORKERS` (default 4). On the real store the backtest takes about 21 minutes with 4 workers, down from 74, and `hockey-model fit --workers N` takes about 6 minutes, down from 20. [feat:model]
- Add `scripts/backtest_golden.py` and a golden test that hash the backtest report, the per-game rows, and the fitted weights on the seeded store with floats rounded to nine decimals, so a speed change that moves a number fails the test. The script also writes the exact hashes of the report and the CSV. [chore:test]
- Install the locked runtime dependencies (`uv export` of `uv.lock`, with hashes) before the wheel in the wheel smoke test, and install the wheel with `--no-deps`, so the smoke job tests the tree that `uv.lock` pins. [chore:ci]
- Validate the experiment records and the check output with `jsonschema` (Draft 2020-12), the first runtime dependency, instead of a hand-written interpreter. An error names the JSON path, the schema, the failing rule, the fix, and the count of errors it does not show. A pattern matches the whole string, so `0001-x\n` is refused. A keyword or a format that nothing enforces, a NaN, and a value JSON cannot hold are refused too. A roster player with a bad `eligible` value is refused with the player id and the value. [refactor:experiments]
- Add the backtest runner, the sharded build, the worker units, and the golden check to the mutation run, and kill their survivors with tests. The mutants that no test can kill are listed with their reasons in `docs/design/mutant-survivors.md`. The mutation shards place the four new modules. [test:backtest]
- Add `docs/design/tla-scope.md`, which says what a TLA+ model of this project may and may not claim. [docs:tla]
- Add `hockey-model store gaps --live`, which lists each live feed that is a known gap as JSON (`source`, `url`, `gap_since`, `age_hours`, `last_ok`, `over_limit`), and `scripts/check-live-feeds.sh`, which the `daily-report-check` workflow runs. The job fails for a live feed that stays a gap for longer than `LIVE_FEED_MAX_AGE`, and for a live feed whose newest read is older than that. [feat:ci]
- Add a `notes` list to the `experiments check` output. It says `deletion history not checked` and the reason when the check runs outside a git work tree or before the first commit. [feat:experiments]
- Add `scripts/manual-prepare-pending.sh` and a `gate` job to `daily-prepare`. A scheduled run stands aside while a manual run waits or runs, so it no longer cancels a waiting forced prepare. The store group moves from the workflow to the `prepare` job, and `prep-running.sh` reads only the start of the `prepare` job. [fix:ci]

### Changed

- A fit with no `--through-season` records the newest season that holds a final game, not the season that holds today. The old cutoff named a season whose games the fit never read, so `result.training` marked the first games of that season in sample. [fix:model]
- A fit also records a game cutoff, which is the start of the newest final game that it read, and `result.training` needs both bounds. The season alone still marked a live fit's later games in sample, so a game that starts after the fit read the store is now `out_of_sample`. A fit saved before this value existed uses its save time as the bound, because no game that starts after that time was final. The value is stored in the saved weights, so the schema version does not change. [fix:model]
- `hockey-model fit` refuses an explicit `--through-season` newer than the newest stored final game, because that cutoff named seasons the fit never read. [fix:model]
- `result.training.membership` uses the stored season of the game, not the season of its Eastern game day. The 2020 bubble is stored as 2019-20, and its September starts fall on the 2020-21 game day. [fix:model]
- Lower `timeout_multiplier` for mutmut, so a hung mutant of `block_bootstrap_mean_ci` stops sooner and the pre-push mutation check finishes inside its limit. [chore:test]
- Move the publish decision of the report gate into Python (`hockey-model report-decide`), so `scripts/report-gate.sh` only reads the schedule and the release. [chore:report]
- Read `data_cutoff` of a confirmation record as "data through this day", so games of the cutoff Eastern game day are no longer in the cohort. [fix:experiments]
- Predict a game that is over in the daily report, from the inputs known at its puck drop, so a late first report is full. A postponed game still gets no prediction. [feat:report]
- The attempt-form and expected-goals reads skip a MoneyPuck team game with a missing value, instead of failing on it. The 10-game window reaches one game further back in that case. [fix:store]
- The daily report run logs the seconds of each step and fails once it passes the limit in `REPORT_BUDGET_S`. The build job fails on a store cache miss. [chore:ci]

- Record the DraftKings comparison in the README, the backtest report, and the run report. The model is level with the line in 2024-25 and worse in 2025-26, and it fails the blend gate. [docs:backtest]
- Move the store to schema version 2, which adds MoneyPuck shot-attempt counts. A version 1 store is refused, so rebuild it on a new path with `hockey-model refresh --backfill-from 2014-10-01`. [feat:store]
- Require `--features` in `hockey-model fit`. The old default fitted every candidate, including `goalie_gsax`, which the backtest vetoed, and the daily report served that fit. `scripts/daily-prepare.sh` now runs the backtest first and fits on its `live_features`, so a failed joint test serves the Elo alone. [fix:cli]
- Name the feed games that fall outside a game day's window in the `report-due` output, instead of dropping them without a word. [refactor:report]
- Replace the daily report's release files and notes with each later build before the first puck drop. The release can therefore change until then, and its notes say so. [feat:report]
- Keep each daily report build as its own `report-DATE-HHMMSSZ` file, named by its `generated_at` time, so a rerun no longer replaces a published version. The `report-DATE` files stay as the alias for the newest build. [fix:report]
- Run `daily-prepare` at minute 14 and `daily-report` at minute 44 of every hour. A late or failed run is retried within the hour, and a confirmed goalie reaches the release within the hour. A report run that finds no prepared marker skips before the first puck drop and fails after it. [feat:report]
- Remove `TRIGGER_HOURS_UTC`, `scripts/trigger_hours.py`, `PREP_WINDOW`, `PREP_QUEUE_ALLOWANCE`, `PREP_CRON_HOUR_UTC`, `prep_too_early`, and the `prep_too_early` field of `report-due`. `report-due` still says `puck_drop_passed`. [refactor:report]
- Remove `noted` and `AbandonedIsNoted` from the daily prepare TLA+ model. The model had its own copy of the note, so the property proved the model and not the code. `test_every_abandoned_url_is_noted` checks the note against the code instead. [fix:tla]
- Give each Hypothesis example its own store or directory in the store, runner, and report tests, so no example sees the state of another, and drop the health-check suppressions that hid this. [test:hygiene]
- Make a streak of permanent HTTP failures, such as 403, a known gap on the second failed read, with no wait for `ABANDON_MIN_SPAN_DAYS`, so a blocked feed no longer costs a slate. `source_reads` gains a nullable `permanent` column (store version 6), and a row from an older store counts as transient. The TLA+ model gains `BlockedScore` and `BlockedBox`. [fix:store]
- Fail `experiments check` when a confirmation record that never ran is deleted while a higher confirmation record existed in the deleting commit, so its number cannot go to a new record. A deletion from before any higher record existed stays allowed. [fix:experiments]
- Put a source gap on the game rows when its season is the season before the current one, and say in the footer that older gaps move a win chance by less than `OLD_GAP_MAX_SHIFT_PP` percentage points. The number comes from a replay of Elo on the real store (`docs/design/elo-gap-effect.md`). [fix:report]

### Fixed

- Fix the gate step of `daily-report`, which failed on every run where `due` or `publish` was false, because `jq -e` exits 1 for a false value. `scripts/gate-outputs.sh` checks the type of each gate field and prints the step outputs. [fix:ci]
- Fix the publish job so two publishes of one day run one at a time, because the index asset is a read-modify-write. The release token now reaches only the publish script step, and the version names are both checked before either upload, so a name collision leaves no half-published build. [fix:ci]
- Move the store to schema version 5, which makes `source_reads.fetched_at` and `model_fits.created_at` NOT NULL. An earlier change made the two columns NOT NULL in the schema without a migration step, so an upgraded store kept the weaker shape and accepted a row with no timestamp. The upgrade refuses to run when a stored row holds a NULL in either column, and names the table and the count. [fix:store]
- Read the shape of the tables before the upgrade trusts the version stamp, so a store stamped higher than its tables can recover. A stamp written while the table kept the old shape made the upgrade skip the changes the store had lost, and the next query failed with `no such column`. The stamp, the changes, the views, and the ledger row now commit together. [fix:store]
- Name the cause of every store failure instead of a permission bit. Each `sqlite3.Error` and each `OSError` printed "check the file path and permissions", so a damaged store, a full disk, a lock, and a missing column all sent the reader after two things that were not wrong. Each cause now names its own fix, a missing column or table points at `hockey-model store upgrade`, and a cause with no match says so. [fix:cli]
- Check the table shape when the store opens, in the producer and in the consumer. A store stamped at the current version with a missing column opened, and the first read that named the column failed far from the cause. It is now refused at open with the upgrade command. [fix:store]
- Stop the ESPN goalie and injury feeds and the Daily Faceoff feed from failing the run once earlier reads left the URL as a known gap. Only the MoneyPuck files honoured the gap rule, so a host that blocks the runner address, such as Daily Faceoff with HTTP 403, failed every run and stopped the daily prepare until a person cleared it. A feed is still read on every run, so one good read clears its gap, and a feed that stays a gap still shows as a stale source on each prediction. [fix:store]
- Read a missing release from the HTTP status in `check-daily-report.sh`, `report-gate.sh`, and `publish-daily-report.sh`. The scripts matched the words "release not found", so a wording change in `gh` moved the check the wrong way. The repository is read first, because GitHub answers 404 for a repository that the token cannot see as well as for an absent release. [fix:scripts]
- Fail a game day whose feed lists every game outside the day window, and warn on a day that drops some of them. `report-due` dropped those games and the check read the zero count as an off day, so a feed keyed to the wrong date passed. `report-gate.sh`, `check-daily-report.sh`, and the prep branch of `daily-report.sh` now read the dropped count, and none of them defaults a missing field to zero. [fix:report]
- Treat a trailing block comment as a comment when a store migration script is split, so a script that ends in `/* note */` is not refused as an incomplete statement. [fix:store]
- Move the store to schema version 4, which adds `attempts_known` to a version 2 store that the earlier code wrote without it. Commit `62cc6fb` added the column to the schema without a version bump, so `hockey-model store upgrade` called such a store current and the first attempt-count query failed with `no such column: attempts_known`. The new step rebuilds `mp_team_games` and derives the flag from the counts. [fix:store]
- Upgrade the restored store at the start of `daily-prepare.sh` and `daily-report.sh`. The store cache holds a file that older code wrote, and the schema version check refused it, so every scheduled prepare run from the version 3 bump to this fix stopped before it read a source and no daily report was written. A missing store file is skipped with `store upgrade --if-missing skip`, because the first backfill writes a current version. [fix:store]
- Leave the same count of bootstrap means outside each end of the interval. The upper end moved one rank lower, so a promotion needs a slightly stricter result. [fix:backtest]
- Judge source staleness in one pass over the read log, so the daily predict step takes seconds and not minutes on a backfilled store. The build job no longer fails its report budget on this step. [fix:report]
- Stop a postponed row from hiding a late daily report in `check-daily-report.sh`. [fix:report]
- Publish the first daily report of a game day even when the run starts after the first puck drop, with a `late` gate reason and a warning. Before this, a late trigger published nothing. [fix:report]
- Fail a backfill that the time budget stops before it reads one older day or game. The last two days do not count, because a daily run completes the day that closed since the last run. Before, each run read the same recent days, stopped, and exited 75, so the backfill never finished and nothing said why. The refresh now exits 1 and names `--budget-seconds`. [fix:store]
- Read a failed NHL score day again on the next refresh, for 30 days. A day that failed and was followed by a good day was never read again, so its games were missing from the Elo and the fit. [fix:store]
- Refuse a boxscore that does not have exactly one starting goalie for each team. A boxscore without a goalie made the next refresh stop with a database error. [fix:sources]
- Read MoneyPuck numbers as plain ASCII decimals. A value such as 1_0 or a non-ASCII digit was accepted. [fix:sources]
- Refuse an ESPN return date that is not text, and a saved fit with an unknown feature or a weight that is not finite. [fix:sources]
- Match an injury name to the goalies of its own team only. [fix:model]
- Print the type and message of an unexpected failure in the store commands. [fix:cli]
- Note in the backtest report that the goalie guess run has no injury history. [fix:backtest]
- Publish the daily report at the first run that starts before the first puck drop. A run that starts after the puck drop publishes nothing and writes a warning. [fix:report]
- Fit the daily-prepare job timeout to the window before the next trigger hour. [fix:report]
- Publish no daily report for a game day with no games, so a failed schedule read cannot leave a wrong release. [fix:report]
- Give the daily report step its own time limit, so a hung read cannot hold the store for the full job limit. [fix:report]
- Allow an hour for the MoneyPuck team file, which is about 130 MB, instead of 15 minutes. [fix:sources]
- Check a fit before it is saved, accept every supported feature including `attempt_form`, reject a feature named twice, and predict with the features that the loaded fit names. A saved attempt-form fit failed with a `KeyError` at prediction. An Elo-only fit still credits MoneyPuck, since the goal rates use its data. [fix:store]
- Install the pre-push hook with a plain `prek install`, so the local coverage gate runs. [fix:ci]
- Name the editorconfig-checker config `.editorconfig-checker.json`, the name the tool loads, and download its archive into `RUNNER_TEMP`. [fix:ci]
- Check that a flag has a value in the report scripts, so `semgrep` parses them and a missing value gives a usage error. [fix:scripts]
- Report a `TypeError` from a model as an unexpected failure. Only a JSON encoder `TypeError` is a serialization failure. [fix:cli]
- Skip an abandoned MoneyPuck team file on later refreshes, as the goalie files are skipped. `refresh --retry-skipped` reads it again. [fix:store]
- Show a source gap that is outside the scored and current seasons once in the daily report footer, and not on every game row. The JSON report lists the same gaps under `training_gaps`. [fix:report]
- Use one season boundary (`SEASON_START_MONTH`) and one season id formula for the fit, the cohorts, and the MoneyPuck refresh. [fix:model]
- Check every projection at each public entry point and refuse a value that is not finite, is out of range, or has an interval that does not hold the point. Goals against average may exceed one. [fix:api]
- Refuse a boxscore that does not name the stored game's teams in the stored home and away order, or that has no skater rows or no starting goalie for a team. A game with one side stored is queued again and repaired without a change to the old rows. [fix:sources]
- Read an unresolved game again after a wait, even when newer games are final. At most `MAX_UNRESOLVED_DAYS` days are read in one refresh, and the report names the games. [fix:store]
- Judge each source URL by its newest read and by age. A good read of one URL no longer clears a failed read of another, and an injury list older than `LIVE_FEED_MAX_AGE` is not used. [fix:store]
- Check a goalie supplied on a `Game` against the earlier of `as_of` and the start, and give it the same uncertainty note as a stored read. [fix:model]
- Leave a goalie out of the starter guess when the games show that the goalie had left the team. A goalie that a source names is not filtered. [fix:model]
- List a form feature that was set to `NEUTRAL_FORM` because a team had no MoneyPuck games in `degraded_inputs`, in the result, the command line output, and the daily report JSON. [fix:model]
- Show the scored games of each season and game type in the backtest report. Refuse `success` and leave `live_features` empty when a listed regular season is under `MIN_SEASON_COVERAGE` of its expected games, or when the scored games hold fewer than `MIN_INDEPENDENT_BLOCKS` blocks for the bootstrap. The bootstrap now raises for such a sample. [fix:backtest]
- Name the Eastern game day, not the UTC day, in the `daily` help, the daily report module docstring, and the `--date` help of `publish-daily-report.sh`. The code already selected the Eastern game day. [docs:cli]
- Read a finished score day again only until 7 hours after the Eastern game day closes, which is 12:00 UTC in winter and 11:00 UTC in summer. The old rule read a summer day one hour too long. [fix:store]
- Set a goalie differential to the neutral value when either starter has no rate, and mark the feature as imputed for that team. The other starter's rate no longer passes through as a measured difference. [fix:model]
- Refuse a fit, with exit 2 and no saved fit, when a selected feature is imputed in more than 10% of its training rows. A backtest vetoes such a candidate instead of stopping. The `imputation` list in the fit and backtest JSON gives the count and share for each selected feature. [fix:model]
- Skip a scheduled report run that finds no prep marker while the morning prep window is still open, with a notice and exit 0, instead of failing red. The window now opens at the prepare cron and closes 180 minutes plus a 60-minute queue allowance later, on the clock, so it closes on a game day with no games. A run whose prepare holds the store group past the first puck drop also skips, with reason `prepare-wait`, because a job timeout counts from its start and would hold the report past the drop. [fix:report]
- Fail the mutation job when the report marks the run `execution_failed`. The gate read its own variable, so a bad stats file left the job green. [fix:ci]
- Document an external clock that will start the daily report at each publish slot, with the GitHub schedule kept as a fallback. GitHub's schedule ran the 23:44 UTC slot about an hour late on two days. The clock runs only after the owner provisions it. [docs:report]
- Stop a backfill from blaming `--budget-seconds` when a source failure stopped it before the budget ran out. [fix:report]
- Read the MoneyPuck season and its staleness URLs from the Eastern game day, so they agree with the game cutoff near the season boundary. The dated score-day check reads the current season from the Eastern game day too. [fix:store]
- Judge the mutation report on every ref, and read all four job results, so a failed shard, merge, or export names itself in the report instead of leaving a clean-looking counts table. The issue write stays on the default branch. [fix:ci]
- Fail the mutation report when the open-report search reaches the `gh --limit` cap of 1000, because an open report past the cap would be missed and a second one would open. [fix:ci]
- Name the unresolved days that the `MAX_UNRESOLVED_DAYS` bound leaves out of a refresh. [fix:store]
- Balance the mutation shards by measured run time instead of file count, and name a shard that leaves mutants unrun. CI measured 357, 707, 3635, and 5355 seconds of mutant work per shard, so the heaviest shard used its whole 25-minute step limit and timed out. The merge now reports a shard whose mutants carry no result, which a killed shard hides because it still uploads a null for each mutant it never reached. [fix:ci]
