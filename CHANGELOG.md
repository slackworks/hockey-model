## [Unreleased]

### Added

- Keep the bytes that each source returned, as schema version 9 (#82). `payloads` holds one body per content hash, compressed with zlib, with the size that the body had before compression, and `observations` holds one row per fetch with its source, URL, key, time, status, parser version, and hash. The capture wraps the HTTP client for the length of one unit of work, so every read that a refresh makes is archived with no change to a source module. A failed unit keeps the bytes that did arrive, so a parser fix can read them again. An ESPN payload loses `pickcenter`, `odds`, and `againstTheSpread` at any depth before the hash, because the model reads no price data. The MoneyPuck team file records its fetch and keeps no bytes. A fetch that an expected absence excuses, such as the goalie file of a season with no published file, also writes its observation, so the archive says what the request returned. An observation status names the stage that failed: `http_error`, `shape_error`, or `store_error`. A request that failed keeps its own status, so a good response beside a failed one stays `ok`, and a parser failure marks the bytes that the parser rejected. `RefreshRun.attempt` refuses a source that `KNOWN_SOURCES` does not hold, so a new source cannot lose its bytes by accident. Design: `docs/design/payload-archive.md`. [feat:store]
- Add a TLA+ model of the experiment registry (`specs/experiment_registry.tla`, design in `docs/design/experiment-registry-tla.md`). It checks that a record with a result keeps its frozen fields, that a result stays and is not replaced, that two records with a result never share a look number, that no more than `MAX_LOOKS` records spend a look, and that a withdrawn record never ran, across commits, deletions, renames, merges, and squash merges. The `registry` shard of `specs/shards.json` runs it when a file of `src/hockey_model/experiments/`, a record under `experiments/`, or the spec changes. The design note lists ten break tests and two gaps that the checks leave open (#307, #308).
- Add a TLA+ model of the store upgrade (`specs/store_upgrade.tla`, design in `docs/design/store-upgrade-tla.md`). It checks the lock, the copy, the changes of each version in one transaction, the shape probe, the ledger row, and the stamp across a crash at every step and two upgrades at once. The `upgrade` shard of `specs/shards.json` runs it when the upgrade code or the spec changes, and a change of a spec now starts only the shards that run that spec. [feat:store]
- Reuse the feature rows of a finished season between daily runs. A backtest or a fit on a store file reads a season from the `season-rows` directory beside the store file when its key has not changed, and builds only the seasons whose key changed. This holds for one worker too. The key of a season is a running hash of the final games, the MoneyPuck rows, the boxscore goalie rows, the injury reads, and the goalie catalog through that season, with the feature list, the burn-in season, and the source files of the package. `daily-prepare.sh --force` deletes the cache. A season keeps the files of the newest `KEEP_FEATURE_LISTS` feature lists for each goalie mode, so a series of experiments cannot grow the directory without limit. [feat:backtest]
- Shard the TLC run. `specs/shards.json` names each shard with its spec, its config, and the paths that start it, and `scripts/tlc_shards.py` reads the map for `scripts/tlc.sh` and for the workflow. `tlc.sh --list` prints the shards, and `tlc.sh --shard NAME` runs one. The `tla` workflow has a plan job that picks the shards that a change reaches, and one job for each shard, named for it. A change that no shard covers starts no TLC job. The refresh command moved to `store_cli_refresh.py`, so a change of the fit command starts no shard. [feat:tla]
- Keep the age of each day in the daily prepare TLA+ model (`age`, `CutoffTicks`), so the model checks the `BACKLOG_BEFORE` cutoff as a tick count and not as a set of days that closed since the last run. `StallNeedsBacklogOrNoHeadway` checks that the stall error needs old work that is still unread, or a run that finished no unit. The main config keeps a one-tick cutoff, because the code cutoff multiplies its states by more than two (#188). `specs/daily_prepare_cutoff.cfg` checks every property at the code cutoff, and `specs/daily_prepare_recent.cfg` checks a run with only recent days left. [feat:tla]
- List each timed-out mutant in the weekly mutation report, with its estimated test time and its CPU limit, so a reader can tell a hang from a limit that moved between runs. `scripts/mutation_timeouts.py` writes the list from the `.meta` files of mutmut, and the report shows up to 20 mutants. [chore:test]
- Log the progress of every long command to stderr, in one format from one module (`progress.py`). A step logs `start`, a `tick` at a set interval, and `end` or `stop` with the time it took. The refresh shows each backfill window with the count read and left, the budget left, and the reason it stopped. The backtest and the fit show the count of finished units. `scripts/run-step.sh` gives `daily-prepare.sh` and `daily-report.sh` the same lines, and it replaces the `step NAME took Ns` line of `daily-report.sh`. The JSON on stdout does not change. [feat:cli]
- Add a model-uncertainty range beside each win chance. The logistic fit keeps the inverse Hessian of its penalized loss, `home_win_interval` turns it into a range at the report level by the delta method on the log-odds scale, and the report JSON has an optional `win_interval` object for each game (`schema_version` stays 1). The Markdown table shows the range in brackets, and a footer says that the range is model uncertainty only. A fit saved before this change has no covariance and so no range, until `hockey-model fit` runs again. [feat:report]
- Open the release notes of a daily report with one line for each game, such as `TOR at MTL: TOR 58% (52–64%)`, through the new `hockey-model report-summary` command. A game with no prediction, an Elo-only fit, and a day with no games each say so. [feat:report]

### Changed

- A fit with no `--through-season` records the newest season that holds a final game, not the season that holds today. The old cutoff named a season whose games the fit never read, so `result.training` marked the first games of that season in sample. [fix:model]
- A fit also records a game cutoff, which is the start of the newest final game that it read, and `result.training` needs both bounds. The season alone still marked a live fit's later games in sample, so a game that starts after the fit read the store is now `out_of_sample`. A fit saved before this value existed uses its save time as the bound, because no game that starts after that time was final. The value is stored in the saved weights, so the schema version does not change. [fix:model]
- `hockey-model fit` refuses an explicit `--through-season` newer than the newest stored final game, because that cutoff named seasons the fit never read. [fix:model]
- `result.training.membership` uses the stored season of the game, not the season of its Eastern game day. The 2020 bubble is stored as 2019-20, and its September starts fall on the 2020-21 game day. [fix:model]
- Lower `timeout_multiplier` for mutmut, so a hung mutant of `block_bootstrap_mean_ci` stops sooner and the pre-push mutation check finishes inside its limit. [chore:test]

- Read `data_cutoff` of a confirmation record as "data through this day", so games of the cutoff Eastern game day are no longer in the cohort. [fix:experiments]

### Fixed

- Accept a status that this code does not name, in the ESPN injury feed, the ESPN probable-starter feed, the Daily Faceoff starter page, and the NHL score feed's `lastPeriodType`. Each parser raised on an unknown value, so one new label failed the whole read, the URL became a known gap after two failures, and the report hid the error. A value now parses, stores as written, and adds one note that names it. An injury status that is not `Day-To-Day` counts as out, so the injured-goalie rule stays safe. The injuries and score parsers take version 2 (#325). [fix:sources]
- Let a cancel stop the `prepare` job of `daily-prepare` and the `publish` job of `daily-report`. The condition of each job starts with `!cancelled()`, because GitHub keeps an `always()` job true after a cancel and a person then cannot stop a 180-minute rebuild. The step-level `always()` on the cache save and the backup drop stays. [fix:ci]
- File no mutation issue for a run that a person cancelled. The merge, report, and file jobs of `mutation.yml` use `!cancelled()` with the same gate, because an `always()` job still filed an `execution_failed` issue on main. A shard that hits its step timeout still fails and still reaches the report. [fix:ci]
- File a mutation issue when the gate job of `mutation.yml` fails. A failed run lookup left the `go` output empty, so the report and file jobs were skipped and mutation testing on main could stop with no alert. `report-mutation.sh` takes `--gate-result`, so the issue body names the gate as the cause. [fix:ci]
- Stand the scheduled mutation run aside only for a manual run of `main`. A manual run on a feature branch counted, so the scheduled run of main stood aside and that week had no main report. `manual-prepare-pending.sh` takes `--branch NAME`, and the gate of `mutation.yml` passes `main`. The prepare workflows keep the any-branch answer, because one store group serves every branch. [fix:ci]
- Give a prepare run that just started its longest window. GitHub lists the jobs of a run one at a time, so a run seconds old listed only its `gate` job, which holds no store group, and the run read as no prepare. The report gate could then let a replace build run into the puck drop. `prep-running.sh` counts such a run until its gate job completes. [fix:ci]
- Check the order of the interval ends before a confirmation run writes any file. A run where every per-game difference was equal gave a zero-width interval, and the check ran after the games CSV and the `--games-out` file were written. The error now names the record, the interval, and the scores to check. [fix:experiments]
- Keep the write token out of the package commands of `publish-daily-report.sh` and `report-mutation.sh`. Each step exported a write token as `GH_TOKEN`, so `report-index`, `report-summary`, and the issue reads ran with it in the environment.
